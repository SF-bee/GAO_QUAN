## [L-ERR] 图论-最小环逻辑漏洞（2026-06-13）

**题目**: 学校景点最优路线（求无向图最小环）

**错误症状**: WA

**根本原因**: Floyd-Warshall 后直接枚举边 $(i,j,w)$ 计算 `w + g[i][k] + g[k][j]`，但 `g[i][k]` 和 `g[k][j]` 的最短路可能本身包含边 $(i,j)$，导致该边被计算了多次。

**反例**:

```
边 1-2: 100
边 1-3: 1
边 3-2: 1
```

Floyd 后 `g[1][2] = 2`，但对边 (1,3) 计算时：

- `f[1][3] + g[1][2] + g[2][3] = 1 + 2 + 1 = 4`（错）
- 实际边 (1,3) 在这个"路径"中被走了 2 次

**修复方案**: 对每条直接边单独隔离处理，计算不经过该边的 u→v 最短路，或使用三层 Floyd 的分层思想。

## T849061 【1115 C】分组方案（2026-11-19）

代码：[T849061.cpp](../Code/Luogu/T849061.cpp)。最终已 AC。

固定组时间窗口 $[L,R]$ 后，使用列向量转移：

$$
\begin{pmatrix}f_i\\f_{i-1}\end{pmatrix}
=M_i\begin{pmatrix}f_{i-1}\\f_{i-2}\end{pmatrix},\qquad
M_i=\begin{pmatrix}[L\le a_i\le R]&[L\le a_{i-1}+a_i\le R]\\1&0\end{pmatrix}.
$$

边界为 $f_0=1,f_{-1}=0$，$M_1[0][1]=0$。本次实现中的问题如下。

1. **矩阵在线段树中的合并顺序反了。** 连续转移的结果是 $M_nM_{n-1}\cdots M_1$，所以父节点应为“右儿子乘左儿子”。建树和单点修改的向上合并都要保持这个顺序：`tre[i] = tre[i << 1 | 1] * tre[i << 1]`。矩阵乘法不能交换顺序。

2. **答案取错矩阵元素。** 原来取根节点的 `M[0][1]`，应取 `M[0][0]`。设根矩阵为 $P$，则 $f_n=P_{0,0}f_0+P_{0,1}f_{-1}=P_{0,0}$。写完矩阵后要实际乘一次初始向量，确认答案位置。最小检查：一个合法任务对应的矩阵为 `{{1,0},{1,0}}`，答案是 1，而右上角为 0。

3. **把右侧开区间端点当成了有效下标。** `r` 指向第一条尚未加入窗口的记录，当前记录范围是 `[l,r)`。删除同值记录时应写 `nxt < r`，不能写 `nxt <= r`。当 `r == p.size()` 时，后者可能访问 `p[p.size()]`；必须先检查边界，再访问元素。

4. **中间表达式溢出 `int`。** 单组时间不超过 $10^9$，双组时间不超过 $2\times10^9$，但枚举的 $L$ 可能达到 $2\times10^9$，因此 $L+D$ 最大达到 $4\times10^9$。本次将 `L,R` 都改为 `long long`，使 `L + D` 在 64 位下计算。仅把接收结果的 `R` 改为 `long long`，不能防止两个 `int` 相加时先溢出。

5. **减法取模没有处理负数。** 改为 `ans = (ans + ans1 - ans2 + mod) % mod`。虽然实际方案数满足 $f(L,R)\ge f(L+1,R)$，两者取模后的大小关系可能反过来；C++ 的负数 `% mod` 仍可能为负数。

6. **大型全局数组的非零默认初始化导致编译产物膨胀。** 原来 `Node` 中写 `ll M[2][2] = {{1,0},{0,1}};`，数组 `tre[MAX << 2]` 有约 80 万个节点。该 GCC 构建把大量初始值放进 `.data`，即使注释主程序逻辑，仍生成约 28.8 MB 的汇编、25.6 MB 的可执行文件；平台报告 `Nothing is compiled: OUTPUT exceeds.`。这不是运行时输出过多，也不是矩阵乘法的语法错误。

   本次实际通过的写法是 `ll M[2][2];`，在 `Build()` 中运行时初始化叶子。由于 `zkw` 是全局对象，其矩阵存储先被零初始化；本地 GCC 13.3、C++14、`-O2` 下，当前版本将大对象放进 `.bss`，启动代码再设置 `N = 1`，完整程序的可执行文件约 21.9 KB。`.bss` 主要记录所需大小，加载时提供零值存储，不必在文件里保存每个零；程序运行时仍然需要这块内存。

   这里不能推广成“局部数组不初始化也为零”，也不能断言“所有非零初始化一定造成大文件”。尤其是 `Node res;` 的成员没有自动清零，本次乘法会在返回前赋值全部四个元素，因此不依赖旧值。补齐叶子必须在运行时设为单位矩阵，实际任务叶子初始设为 `{{0,0},{1,0}}`；不能让补齐叶子保留零矩阵，否则整个乘积会被清零。

   辅导时曾建议必须把 `N = 1` 也改掉，这一说法过于绝对：当前 AC 代码保留了它。本次现象与矩阵成员的初始化方式及编译器对整个对象的初始化实现有关；全零默认值再运行时初始化是另一种可行写法。

7. **把警告和真正的编译失败信息混淆了。** `int` 类型的 `l,r` 与无符号的 `p.size()` 比较会产生 `-Wsign-compare` 警告；通常不会导致编译失败，除非启用 `-Werror` 等设置。本次真正需要排查的是后面的 `OUTPUT exceeds`。若要消除警告，可以先写 `int m = static_cast<int>(p.size());`，再与 `m` 比较；本题最多 $2n-1=399999$ 条记录，转换安全。
